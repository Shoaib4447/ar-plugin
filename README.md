# Frame Lab — multi-product eyewear try-on

This prototype runs one browser-based fitting engine across a product catalog.
Each frame supplies physical dimensions through a versioned manifest; shoppers
can switch products inside one camera session and optionally set their pupillary
distance (PD) for more meaningful physical scale.

## Run locally

Requirements: Node.js 20+ and pnpm.

```powershell
pnpm install
pnpm dev
```

Open the URL printed by Vite and select a frame. Camera access works on
`localhost`; other devices require HTTPS.

## Implemented

- Three-product catalog loaded from `public/catalog/products.json`.
- Product switching without recreating the camera or face tracker.
- PD-aware frame sizing that preserves differences between product widths.
- Automatic legacy depth normalization from frame and temple measurements.
- MediaPipe face inference in a Web Worker at up to 30 FPS.
- Live MediaPipe face-mesh depth occlusion instead of an ellipsoid.
- Product fit estimate (`narrow`, `balanced`, or `wide`).
- Local camera processing and persisted PD preference.
- Catalog/GLB validation through `pnpm validate:catalog`.

## Asset status

The three supplied GLBs are retained as `legacy-demo` assets. They are 52–66 MB,
contain 1.36–1.74 million triangles, and use one fused mesh and material. The
runtime automatically infers a bridge and provides a texture-based lens fallback
only so the catalog flow can be tested.

Production products must follow [the eyewear asset contract](docs/ASSET_CONTRACT.md):
separate named frame/lens/temple nodes, verified dimensions, bridge and hinge
pivots, physical lens materials, and mobile-sized geometry/textures.

## Validate and build

```powershell
pnpm validate:catalog
pnpm build
```

`assetStatus: "production"` products fail validation when required semantic
nodes, lens transmission, or performance budgets are missing. The current
`legacy-demo` products emit warnings instead.

## Next integration boundary

For Shopify, the theme app extension should render the Try On entry point and
pass a product/variant manifest generated by the app backend. Product metafields
should contain the public manifest reference and processing state; original and
optimized asset records, validation reports, and merchant configuration belong
in the app database.
